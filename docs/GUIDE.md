# How the Japan trip guide is built

This is the full write-up of how the guide at **https://japan.zhunior.com** works: where the content lives, how a new version is made and published, and how to grow it into other trips and countries later.

- **Live site:** https://japan.zhunior.com (GitHub Pages, from this repo's `main` branch)
- **Current version:** shown in the page footer and at the top of `index.html`
- **Source:** the `source/` folder. `index.html` is generated, so never edit it by hand.

---

## 1. What the guide is

It's a single web page, made for phones and for the two people travelling, of *options* rather than a schedule. Each stop on the trip has a tab with:

- a header (illustration, local name, dates)
- the hotel (or starting point) with an "Open in Maps" button, plus a short practical note
- **filters**: "Show" by category and "Feeling" by mood tag, with a live count and "Clear filters"
- **cards**: one per place, with a number, area, distance from the hotel, tags, a short description, and buttons for "Open in Maps", "Photos" (a Google image search) and "Show on map"
- **Pick by area**: a fold-out panel grouping places that are close together
- **a drawn map**: our own SVG map with numbered pins in category colours. Places far away are pinned at the edge with their distance.
- **an embedded Google map**: it follows the pin or card you tap
- a "Next stop" link at the bottom

It also has dark mode (it follows the phone, with an Auto / Dark / Light switch), and it's hidden from search engines.

## 2. Repository layout

```
index.html              the live page (generated by source/build_site.py)
CNAME                   tells GitHub Pages to serve the site at japan.zhunior.com (keep it)
.nojekyll               tells GitHub Pages to serve files as they are
README.md               short overview
CLAUDE.md               working rules for Claude when this repo is attached to a chat
docs/GUIDE.md           this document
source/
  data.py               ALL the content: categories, stops, hotels, places, areas, map settings
  common.py             icons, header illustrations, the map drawing (build_map), small helpers
  styles.py             the base stylesheet (design tokens, layout, components), scoped under #jp26
  build_site.py         builds index.html. Version number and changelog live here.
  test_site.py          automated checks (run before every publish)
  read_gmaps_list.py    reads a shared Google Maps list into JSON (names, notes, coordinates)
  build_mymaps.py       makes one Google My Maps import file (.kml) per stop
  build_pdf.py          older printable PDF (Osaka and Shirahama only, not kept in sync)
  out/                  build outputs that aren't published (git-ignored)
```

## 3. Making and publishing a new version

Requirements: Python 3. The tests, the list reader and the PDF also need Playwright with Chromium (`pip install playwright` and `playwright install chromium`).

1. **Edit the content** in `source/data.py`. See sections 4 to 6.
2. **Bump the version** in `source/build_site.py`: `VERSION`, `VDATE`, and a new line at the top of `CHANGELOG`.
   - `1.3`, `1.4` and so on are for new places, stops or features.
   - `1.3.1` and so on are for small fixes.
3. **Build:** `python3 source/build_site.py`. This writes `index.html`.
4. **Test:** `python3 source/test_site.py`. Every check must pass. Screenshots are saved in `source/out/test/`.
5. **Publish:** commit `index.html` together with the source changes, and push to `main`. GitHub Pages updates in about a minute. To confirm, run `python3 source/test_site.py https://japan.zhunior.com/`, or check that the footer shows the new version.

The build also writes `source/out/squarespace-v<version>.html`, a variant of the page with no JavaScript that fits in a Squarespace Code Block. The guide used to live on zhunior.com/japan that way. That page is frozen at v1.1 and is no longer updated.

## 4. The data model (`source/data.py`)

### Categories (`CATS`)
Each category has a title, a local-language label (`jp`), a colour, a light tint, an icon (a key into `ICONS` in `common.py`) and a default lead sentence. The order of `CATS` is the order of the sections on the page, and places are numbered in that order.

| key | title | colour |
|---|---|---|
| must | Must-eats | #E2604A |
| food | More food (per-stop override, e.g. "Food") | #E8952F |
| sweets | Sweets | #D2648E |
| coffee | Coffee | #9A6B4B |
| drinks | Drinks | #8A5AA6 |
| onsen | Hot springs | #6C7FC4 |
| sights | Sights (e.g. "Temples & sights") | #4F9A6A |
| trips | Day trips / Further out | #3E8FA8 |

The "Food" filter chip includes Must-eats.

### A place
Each place is a tuple:

```
(category, name, area, distance_text, tags, description, maps_url, photo_search_query, lat, lon)
```

- **distance_text** is calculated, not typed. Each stop has a helper (`dist`, `kdist`, `wdist`, `hdist`) that measures the straight-line distance from the hotel and adds "· walk" under about 1.2 km. Kyoto shows two distances ("from hotel 1 / from hotel 2").
- **tags** are free text, but six of them act as mood filters: `Must-go`, `Quick bite`, `Late night`, `Low energy`, `Outdoors`, `Photo spot`. The others just display: `Book ahead`, `Queue`, `Pricier`.
- **maps_url** can be a short link the user sent, a `maps.google.com/?cid=...` link from a Google list, or a search link.
- **photo_search_query** becomes a Google Images search link. We never copy photos from Google Maps, Instagram or restaurant sites.
- Each stop's raw list (`P`, `SH_RAW`, `KY_RAW`, `WK_RAW`, `HK_RAW`) is turned into finished places, and at the end every stop's places are sorted into category order.

### A stop (an entry in `CITIES`)
Required fields:

| field | meaning |
|---|---|
| `key` | short id, used in links (`#jp-city-kyoto`) |
| `name`, `jp` | display name and local-script name |
| `stop` | the stop number shown in the header kicker |
| `dates`, `nights` | e.g. "Nov 23-27", "4 nights" |
| `sub` | header tagline (HTML allowed, e.g. `&amp;<br>`) |
| `art` | key into `ART` in `common.py` (the header illustration) |
| `hotel`, `hotel_name`, `hotel_note` | dict with name/lat/lon/maps, plus display text |
| `day1` | (title, text) for the dark info box, or `None` |
| `planner` | heading above the cards, usually "Options" |
| `places`, `areas` | the places, and the "Pick by area" groups: (name, distance text, [place names]) |
| `leads`, `icons`, `titles` | per-category lead sentence, icon override, title override |
| `map` | drawn-map settings (below) |

Optional fields: `tabdates` (text under the tab name), `hotel2` with `hotel2_name`, `hotel2_note`, `hotel2_dates` and `hotel2_nights` (a second hotel, as in Kyoto), `optional=True` (dashed "maybe" styling, as in Wakayama), `kicker`, `pill`, `hotel_box_title`, `hotel_label` (the map's ★ label), and `next_back` (where the "Next stop" link points, e.g. Hikone back to Kyoto).

Filters switch on automatically once a stop has 8 or more places (`FILTER_MIN` in `build_site.py`).

### Map settings (`map=dict(...)`)
- `k`: map units per km (the scale). `W` and `H`: canvas size (100 wide). `ycenter_shift`: moves the content down to leave room at the top.
- `scale_km` and `scale_lbl`: the scale bar, e.g. 0.5 and "500 m".
- `labels`: area names drawn on the map, as (text, lat, lon, anchor).
- `river`: optional list of (lat, lon) points drawn as a line (the Kamo River in Kyoto).
- `outliers`: places too far away to draw to scale. Each is pinned at the edge: (name or [names], y, label, "left" or "right").

`build_map` projects coordinates onto the canvas, runs a small force layout so that pins don't overlap (each one stays tied to its true spot with a thin line), and adds the hotel star(s). After changing places, look at the map (the test screenshots, or open `index.html`) and move any labels or edge pins that collide.

## 5. Adding places

**From a message.** The user sends a name, a Google Maps link and a line about the place.
1. Get the coordinates. Fetching the short link redirects to a URL containing `!3d<lat>!4d<lon>`, which are the place's exact coordinates. (The `@lat,lon` part is only the map's viewport.)
2. Add the tuple to the right stop. Use the user's own words for the description and pick tags that match what they said.

**From a shared Google Maps list:**
```
python3 source/read_gmaps_list.py <list link> <hotel lat> <hotel lon> > list.json
```
This gives every place with the note the user wrote, its coordinates and distance, and a `?cid=` Maps link. Drop places that are already in the guide, and say which ones you skipped.

**Before publishing, check practical facts** on the place's Maps page or an official site: closed or temporarily closed, the weekly closing day, reservations, seasonal opening, ferry seasons, light-up dates. Put what matters into the description, for example "Closed Wednesdays, which doesn't clash with our dates", and give the user the sources.

**Writing style:**
- Use plain, short sentences. **No long dashes** (the em dash, or a spaced en dash), because they read as AI-written. Use a full stop or a comma instead. Date and distance ranges use a plain hyphen: "Nov 16-20", "4-6 km".
- **No personal names** on the page. The build refuses to finish if it finds them.
- Keep the user's voice ("we've been before", "must go"), and don't invent experiences.
- If a place's name on the map is only in Japanese, use an English name on the card and add "Called 豆の湯 on the map."

## 6. Adding a stop

1. Add the hotel (or starting point) and the place list, following an existing stop. The newest pattern is in `HK_RAW` / `HIKONE`.
2. Add the stop to `CITIES` in travel order. Tabs, "Next stop" links and the per-stop CSS are all generated from that list.
3. Add a header illustration to `ART` in `common.py`. These are small hand-written SVGs on a 200×170 canvas, using `INK` outlines and warm flat colours. Add a matching gradient for `.hero-<key>` in `build_site.py`, in both the light CSS and the dark `HEROES` list.
4. Add any new local-script characters (the `jp` name, new category labels) to `JP_CHARS` in `build_site.py`. The Japanese font is downloaded as a subset containing only those characters.
5. Build, test, and check the map screenshot.

## 7. Growing it into other trips and countries

The engine isn't specific to Japan, but a few things are hard-coded. For a new trip, the cleanest route is **one folder per trip, each published as its own page**:

```
trips/japan-2026/data.py      (today's source/data.py)
trips/korea-2027/data.py
```

Each trip can be its own page: either a subfolder on a shared trips site (for example `trips.zhunior.com/korea-2027/`) or its own subdomain (`korea.zhunior.com`), each through a GitHub repo plus one CNAME record in Squarespace. A plain `zhunior.com/<path>` isn't possible, because the main domain stays on Squarespace. Things to make configurable when doing this:

| What | Where today | Change to |
|---|---|---|
| Brand text "Japan 2026", "Japan trip guide" | `build_site.py` (header, kicker, footer, page title) | a `TRIP` dict in data.py: title, year, tagline |
| Local-script font (Noto Sans JP) and `JP_CHARS` | `build_site.py` font import | per-trip font family (e.g. Noto Sans KR or SC) and its character list |
| Category labels in local script (`jp` in `CATS`) | `data.py` | per trip; the categories themselves can stay |
| Header art | `ART` in `common.py` | add art per stop |
| The `#jp26` wrapper id and `jp-` link prefixes | everywhere (CSS and links) | can stay as is (just a name), or rename to `#guide` |
| Distance helpers per stop | `data.py` | one generic `dist(hotel, lat, lon)` |
| The Squarespace variant | `build_site.py` | can be dropped for new trips |

Keep the shared parts shared: `styles.py` (design), `common.py` (map drawing and icons), the page structure in `build_site.py`, and `test_site.py`.

## 8. Design

- **Look:** warm, cute and readable: cream paper, rounded type, a flat illustration for each stop, and a category colour on each card.
- **Fonts:** Fredoka (headings, buttons), Nunito (body text), Noto Sans JP (Japanese), all from Google Fonts.
- **Colour tokens** (light / dark), defined in `styles.py` and overridden for dark in `build_site.py`:
  - background `#FFF8EE` / `#1C1613`
  - surface `#FFFFFF` / `#28201C`
  - ink `#3A2E2A` / `#F4E8DA`
  - muted `#8A766A` / `#B29D8D`
  - line `#F0E2CF` / `#3B302A`
  - accent `#D9483B` / `#F07261`
  - sun `#F7B267`
- **Dark mode:** the phone's setting applies automatically (`prefers-color-scheme`). The Theme button sets `data-theme` on the page and remembers the choice in the browser. The headers switch to dusk gradients, and the illustrations stay as they are.
- **Mobile first:** a single column on phones, maps folded behind "Show", tabs that scroll sideways, and no sideways page scroll (the tests check this).

## 9. How the interactive parts work

- **Tabs** are plain links to `#jp-city-<key>`. CSS shows the city that is the `:target`, or the one containing the target (so tapping a card's link keeps its city open). It falls back to the first stop.
- **Filters** are hidden radio buttons (category) and checkboxes (mood) styled as chips. CSS `:has()` hides the cards that don't match. The count is a CSS counter. Empty sections and the "nothing matches" message come from generated rules (`minimal_failing` in `build_site.py`). None of this needs JavaScript, which is why the same markup also worked inside Squarespace.
- **Pin dimming:** pins and area chips carry classes for their category (`pc-*`) and tags (`pt-*`), and filtered-out ones fade.
- **Google map:** a keyless embed (`maps.google.com/maps?q=lat,lon&z=..&output=embed`). It shows one place at a time. The script loads each tab's map when the tab opens, and moves it when you tap a pin or "Show on map". Without JavaScript, pins jump to the card instead.
- **The drawn map** is generated SVG. The dot grid is an SVG pattern, which keeps the file small.

## 10. Hosting and domain

- **GitHub Pages:** repo Settings → Pages → Deploy from a branch → `main` / root. HTTPS is enforced.
- **Custom domain:** the `CNAME` file contains `japan.zhunior.com`. The domain is registered through Squarespace. In Squarespace (Settings → Domains → zhunior.com → DNS) there is a CNAME record: host `japan`, data `gpanime.github.io`. If the `CNAME` file is ever deleted, the site falls back to gpanime.github.io/japan-guide.
- **Hidden from search engines:** `noindex, nofollow, noarchive, nosnippet` meta tags. There is deliberately no robots.txt block: it would stop search engines from reading the noindex instruction. The repo itself is public, which is fine, since nothing personal is in it.

## 11. Other outputs

- **Google My Maps:** `python3 source/build_mymaps.py` writes one .kml file per stop: numbered pins, category colours, descriptions, hotels as stars. Import each into a layer of a My Maps map. If pins all come in one colour, use "Group places by: Category".
- **PDF:** `build_pdf.py` makes the original printable guide (Osaka and Shirahama). It would need updating for the other stops.
- **Editable doc:** an early Claude Docs version of the guide exists (Osaka and Shirahama only) and is out of date. The website is now the reference.

## 12. Ideas parked for later

- **A Google map with all pins at once.** Three options were discussed:
  1. A My Maps embed. Free, but it has to be re-imported every time places change.
  2. The Google Maps JavaScript API. The best result and always in sync, but it needs an API key with a billing account (it stays within the free allowance), locked to the domain.
  3. Leaflet with OpenStreetMap. Free, no key, but not Google's look.

  The current single-place embed was judged good enough.
- Shared "been there" ticks between the two travellers. This would need a small database, which GitHub Pages doesn't have.
- Updating the PDF for all stops.

## 13. Short history

- **Osaka guide:** first an editable doc, then a designed PDF.
- **Web version:** first a hosted page, then the Squarespace Code Block. That meant no JavaScript on the Personal plan and about 300,000 characters at most, so filters were rebuilt in pure CSS and the file was slimmed down.
- **Stops added:** Shirahama, Kyoto (two hotels), Hikone, and an optional Wakayama stop. Places came from messages and from shared Google Maps lists.
- **v1.2:** moved to GitHub Pages on japan.zhunior.com, with dark mode and embedded Google maps.
- **v1.2.1:** stronger search-engine hiding. The source and these docs were added to the repo.
